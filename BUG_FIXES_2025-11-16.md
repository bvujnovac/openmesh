## BUG #1: Missing Device-Network Relationship

### Severity: CRITICAL

### Description
The topology API was attempting to access `device.network_id` attribute, but the Device model had no relationship to Network. This caused the entire topology visualization to fail with 500 errors.

###Error Message
```
AttributeError: 'Device' object has no attribute 'network_id'
```

### Root Cause
- Device model lacked `network_id` foreign key column
- No SQLAlchemy relationship between Device and Network models
- Topology API code assumed the relationship existed

### Files Modified
1. `backend/models/device.py`
   - Added `network_id` foreign key column with CASCADE delete
   - Added `network` relationship to Network model

2. `backend/models/network.py`
   - Added `devices` relationship (one-to-many)
   - Imported List type for relationship

3. `backend/schemas/device.py`
   - Added `network_id` to DeviceUpdate schema
   - Added `network_id` to DeviceResponse schema

4. Database Migration
   - Manually added `network_id INTEGER` column to devices table via SQL

### Fix Details
```python
# Device model - added relationship
network_id: Mapped[Optional[int]] = mapped_column(
    Integer, ForeignKey("networks.id", ondelete="SET NULL"),
    nullable=True, index=True
)
network: Mapped[Optional["Network"]] = relationship("Network", back_populates="devices")

# Network model - reciprocal relationship
devices: Mapped[List["Device"]] = relationship("Device", back_populates="network")
```

### Verification
```bash
curl http://localhost:8000/api/v1/topology
# Returns: 5 nodes with network_id correctly populated
```

## BUG #2: Load Average Parsing Failure

### Severity: CRITICAL

### Description
All metrics writing to InfluxDB was failing silently because load average parsing crashed on space-separated format. The code expected comma-separated values.

### Error Message
```
Warning: Failed to write metrics to InfluxDB: could not convert string to float: '0.50 0.40 0.35'
```

### Root Cause
- Code expected load average format: `"0.5, 0.4, 0.3"` (comma-separated)
- OpenWRT/Linux provides format: `"0.5 0.4 0.3"` (space-separated)
- Parsing logic used `.split(",")` which failed on spaces

### Impact
- **Zero metrics** were being written to InfluxDB
- Metrics page would show no data
- Real-time updates were not working
- Historical trending was broken

### Files Modified
1. `backend/api/v1/devices.py` - heartbeat endpoint

### Fix Details
```python
# BEFORE (broken)
loads = [float(x.strip()) for x in status_update.load_average.split(",")]

# AFTER (fixed - supports both formats)
loads = [float(x) for x in status_update.load_average.replace(',', ' ').split() if x.strip()]
```

### Verification
```bash
# Send heartbeat
curl -X POST http://localhost:8000/api/v1/devices/1/heartbeat \
  -H 'Content-Type: application/json' \
  -d '{"load_average": "0.50 0.40 0.35", "cpu_usage_percent": 25.5}'

# Verify metrics in InfluxDB
podman exec openmesh-influxdb influx query \
  'from(bucket: "metrics") |> range(start: -1h) |> filter(fn: (r) => r["_measurement"] == "device_health")'
# Returns: 18 data points (WORKING!)
```

## BUG #3: Topology Link Generation Logic Issue

### Severity: MEDIUM

### Description
The topology API generates zero links between devices because the subnet-based proximity logic doesn't match the actual IP allocation scheme.

### Root Cause
Devices have widely spaced subnet_ids (4, 45, 122, 33, 215) due to deterministic MAC-based hashing. The link creation logic only connects devices in adjacent subnets (diff <= 1), which never matches.

### Current Behavior
```json
{
  "nodes": 5,
  "links": 0,  // Always zero!
  "online_nodes": 4
}
```

### Files Affected
- `backend/api/v1/topology.py` (lines 76-90)

### Status
**DOCUMENTED - NOT FIXED** (marked as TODO in code)

The code includes this comment:
```python
# In a real implementation, links would come from:
# 1. Babel routing table (neighbor relationships)
# 2. WiFi association data
# 3. LLDP/CDP neighbor discovery
```

This is intentional placeholder logic. Real fix requires:
- Babel daemon integration
- Parse `/var/run/babeld.socket` for neighbor data
- Query mesh WiFi associations
- Implement LLDP/CDP discovery
